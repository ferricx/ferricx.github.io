Tab Navigation

Two tab sets built on the ARIA tabs pattern. Each has five tabs, and each tab panel holds a list of five links. The two sets are identical except for one detail: in the second set every list carries aria-labelledby pointing at the tab that owns its panel, so the list is announced with a name. Compare how a screen reader reports the two.

WCAG 2.2 guidance

The lists in these panels have no accessible name. A screen reader announces only “list, 5 items”.

ARIA Authoring Practices

The lists in these panels use aria-labelledby referencing their own tab, so each list is announced with the tab's name.

Accessibility Notes

  • Tab list semantics — The container uses role="tablist", each control uses role="tab", and each panel uses role="tabpanel".
  • Named tab list — Each tablist carries aria-labelledby pointing at its section heading, so the two sets are distinguishable.
  • Selection state — The active tab carries aria-selected="true"; the others carry aria-selected="false".
  • Tab to panel association — Each tab uses aria-controls to reference its panel, and each panel uses aria-labelledby to reference its tab.
  • Roving tabindex — Only the selected tab is in the tab sequence; Tab then moves straight into the panel content.
  • Arrow key navigation — Left and Right wrap through the tabs, Home selects the first, End selects the last, with activation following focus.
  • No panel tabindex — Panels contain focusable links, so they are not added to the tab sequence themselves.
  • Visible focus — Tabs and links show a :focus-visible outline that does not rely on color alone.
  • Selection not by color alone — The selected tab is marked by an accent bar, a border, and a background change, not hue alone.
